# 迭代策略选择

策略不是预制流程名称，而是根据任务事实形成的一组选择。先保留共同底线，再决定反馈节奏、版本关系、人工节点和状态变化规则。

## 共同底线

任何策略都应满足：

- 每代能定位目的、改动、运行、产物、证据和决定；
- 证据强度与结论相称，不把结构正确写成业务变好；
- 评测尺子变化时显式进入 Epoch Review；
- 工作采用、业务校准和生产发布不互相冒充；
- 高风险或不可逆动作保留所需授权、人工 Gate 和回滚。

其它内容是策略变量，不设全局固定答案。

## 策略画像

只判断会改变实际做法的维度。项目已有答案时直接引用，不重复询问。

### 迭代对象

本轮主要改变什么：目标或契约、整体方法、提示词、模型、数据、工具链、局部能力、路由，还是评测本身。不同对象可以属于同一项目但处于不同阶段。

### 版本关系

- **替换**：新版本准备取代当前工作版本；
- **增量**：增加可选阶段、能力或局部模块，原路径仍成立；
- **并行**：多个方案继续共存并积累证据；
- **分流**：按输入、客户、风险或场景路由到不同方案；
- **实验**：只验证假设，不更新工作指针；
- **契约变化**：成功定义或关键边界变化，需要 Epoch Review。

比较对象由关系决定。增量能力应比较受影响 Case，并回归未受影响路径；分流策略应分场景评估，不用一个平均分压平差异。

### 反馈经济性

分别判断每类反馈的：可信度、成本、等待时间、覆盖面、可重复性和可用频率。把现有反馈排成证据梯度，而不是只问“有没有 Gold”。

Gold 便宜且快速时可以每代使用；昂贵或延迟高时，让便宜证据承担日常筛错，在检查点集中校准。没有高层证据时，限制结论，不阻止低风险、可逆的探索。

### 风险与可逆性

判断错误是否外显、是否影响真实用户、能否撤回、是否涉及合规安全或重大损失。风险决定控制强度和指针变更权限，不直接决定 Gold 的固定频率。

### 人工参与

选择符合用户资源和偏好的组合：

- 每代查看 Diff；
- 抽样或只看关键 Case；
- 周期检查点集中复核；
- 低置信度、回归或争议时介入；
- 工作采用、业务校准或生产发布时 Gate。

鼓励人参与意味着把人的判断放在最有价值的位置，不是把每个低价值步骤都变成人工审批。

### 节奏与停止条件

记录运行频率、允许并行多少试验、成本预算，以及何时继续、暂停、校准或结束。检查点可以按代数、时间、样本量、累计改动、风险事件、方向争议或发布准备触发。

## 从画像生成策略

策略至少回答：

```text
迭代对象：...
当前阶段：...；局部阶段：...（仅需要时）
控制强度：轻量 / 标准 / 严格
版本关系：替换 / 增量 / 并行 / 分流 / 实验 / 契约变化
当前工作版本：...
最近业务校准版本：...
生产版本：...
每代最低证据：...
高成本反馈：...
检查点触发：...
人工参与：...
状态变更规则：...
停止或升级条件：...
```

只保留适用项。简单任务用几句话即可，不为了策略卡创建新文档；复杂任务优先写入已有状态页或项目约定。

## 常见策略形态

这些是推导结果，不是要求用户选择的套餐。

### 探索优先

目标模糊、风险低。每代用真实产物和人工反馈澄清问题，不急于建立正式 Baseline 或量化趋势。

### 快速工作循环，周期校准

高可信反馈昂贵或延迟高。每代做运行校验、回归和 Diff，允许可逆的工作版本演进；按检查点集中做业务 Gold，单独更新业务校准状态。

### 增量能力验证

新能力只影响局部路径。保留原方法，比较受影响 Case，回归原路径，并决定该能力默认开启、条件开启、继续实验或移除。

### 并行或分流

没有单一方案适合所有场景。维护多个明确用途的方法，按场景比较并记录路由规则，不强行选唯一全局赢家。

### 高风险旁路

生产或不可逆风险高。Candidate 先 Shadow、Dry Run 或限流运行；人工 Gate、关键回归和回滚准备完成后才更新生产指针。

## 重新选择策略

策略不是永久契约。出现反馈成本变化、任务风险变化、版本从实验转为生产、用户参与方式变化或长期没有获得有效学习时，重新生成策略画像。策略变化本身不一定开启新 Epoch；只有“什么叫做好”改变时才需要 Epoch Review。
