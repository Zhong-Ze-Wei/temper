# 0014 · 静态文件更新机制（v0.0.8）

## 触发（用户反馈）

用户指出：上一版"评测自动载入"让 AI 自己判断有效就写文件，但这属于"静态文件更新"—— 更新测试集/评测说明这类单一权威文件会改变后续所有轮的参照，应该触发 + 问用户，不默默改。同时"评测体系本身要被迭代"的元认知也要写进 temper。

## 根因

v0.0.7 把"自动载入"理解成了"AI 自己判断有效就直接写"。但评测文件是尺子，尺子改了历史可比性就变；是权威定义，改了后续参照就漂。改动它们的代价高于普通运行文件，必须经用户。

## 本代改动

| 文件 | 改动 |
| --- | --- |
| SKILL.md | v0.0.7 的"评测自动载入"升级为"静态文件更新"机制：定义单一权威文件；触发条件（新评测标准/文件脱节/用户说"这该沉淀"）；触发后必须问用户（目标文件+建议更新+影响），确认才写；明确"评测自动载入是静态文件更新的一种" |
| 评测/评测说明.md | 同步：评测载入 = 受控动作，非自动写文件 |

## 静态文件更新机制要点

- **受控文件**：评测文件、README/state/版本说明、方法本体（SKILL.md/references）。
- **触发**：新评测标准 / 文件脱节 / 用户提及"这该沉淀"。
- **动作**：提议（目标文件+建议更新+影响）→ 问用户 → 确认才写 → 记入本代记录。
- **为什么**：这些是尺子和权威定义，改动的代价高于普通运行文件。

## 验证 / 证据

- 机制性改动：把"默默写"改为"提议+确认"。
- 直接修掉 v0.0.7 的缺陷（自己判断有效就写，未过用户）。
- ⚠️ 尚未用真实"新评测标准"验证完整链路（触发→问用户→确认）——需一次真实触发来测。
