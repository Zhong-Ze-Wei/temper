# 最小项目结构

结构的目标是让用户看得懂当前任务并支持可靠迭代，不是让所有项目长得一样。先识别逻辑职责，再映射到已有路径；只有职责缺失且当前阶段确实需要时才创建文件。

## 逻辑职责

按项目需要识别以下角色：

- **定义**：当前目的、边界、成功标准和未知项；
- **状态**：阶段、强度、策略、Epoch、版本关系、当前工作版本、业务校准版本、生产版本、当前节点和下一步；
- **方法**：当前方法、候选修改，以及需要并行或分流的其它方法；
- **评测**：评测口径、样本、Gold、Regression 和结果；
- **运行**：每一代的输入、配置、产物、Diff 和决策；
- **学习**：待验证假设与已验证经验；
- **归档**：不再代表当前规则的历史内容。

目录名称和语言可以不同。已有 README、CURRENT、docs、evals、runs、experiments 或 changelog 能承担角色时直接复用。

## 创建规则

遵循：复用现有文件 → 补充现有文件 → 必要时拆分 → 最后才新建。

- 不创建空目录或占位文档；在第一次实际需要内容时创建。
- 一个逻辑职责只保留一个当前权威来源；README 和索引通常是视图，不是重复事实源。
- 替换式 Candidate 与当前工作版本分开，不能在决策前原地覆盖。增量、并行或分流版本按真实关系组织，不强造 Candidate/Baseline 对。
- 运行产物和决策记录原则上不可变；更正时追加说明或生成新一代。
- 归档必须明确“不代表当前规则”。
- 新文件应从 README、状态页或上级索引可发现；不要制造孤儿文档。
- 只有内容具有不同生命周期、权限、读者或版本需求时才拆成独立文件。

## 默认最小形态

仅当项目没有等价结构时使用这些默认名称。

### 模糊任务或轻量 Discovery

```text
README.md                    # 复用已有首页；必要时增加当前状态块
项目定义/
    当前理解.md              # 当前目的、假设、未知项、下一次学习问题
循环/
    当前状态.md
.temper/
    state.json
```

没有真实运行前不创建 `运行记录/`。目标仍在探索时，`epoch` 可以为空，状态标记为 `exploratory`。

### 标准迭代

```text
README.md
项目定义/
    当前定义.md
循环/
    当前状态.md
    循环总览.md
方法/
    当前方法/                  # 或项目已有工作版本指针
    候选方法/                  # 仅在替换式迭代需要时
评测/
    评测说明.md
    回归案例/
运行记录/
.temper/
    state.json
```

只有实际存在回归 Case 时才创建 `回归案例/`；已有项目可以用单个文件、测试目录或外部评测系统代替。

增量能力可放在现有方法内部或独立模块；并行与分流策略可以保留多个命名方法和路由说明。不要为了符合示例改造用户已经清楚的版本目录。

### 严格控制

从标准形态按已识别风险增加所需内容，例如关键基准、人工裁决、风险与回滚说明或更完整的运行 Manifest。不要一次创建 Anchor、Holdout、Hooks、Runtime、Graph 等所有目录。

## `.temper/state.json`

这是轻量机器状态和路径映射，不保存重复的完整业务定义。建议包含：

```json
{
  "schema_version": 1,
  "stage": "discovery",
  "intensity": "light",
  "strategy": {
    "change_relation": "exploration",
    "feedback_cadence": "per_generation_observation",
    "human_mode": "review_each_round"
  },
  "comparison_status": "exploratory",
  "epoch": null,
  "versions": {
    "working": null,
    "last_business_validated": null,
    "production": null,
    "active_experiments": []
  },
  "current_step": "frame-first-v0",
  "paths": {
    "definition": "项目定义/当前理解.md",
    "status": "循环/当前状态.md",
    "runs": "运行记录"
  },
  "last_run": null,
  "next_action": "生成第一个可观察产物",
  "human_attention": []
}
```

根据阶段只保留有意义的字段。进入正式 Epoch 后，再记录被冻结的定义、评测版本或文件指针。业务内容仍以用户可见文件为准。

## 当前状态视图

用户应能快速看到：

- 当前阶段和为什么；
- 轻量、标准或严格；
- Discovery 的当前学习问题，或正式 Epoch 的冻结内容；
- 适用的版本角色，不要求三个角色都存在或相同；
- 当前变化是替换、增量、并行、分流、实验还是契约变化；
- 最近一代、证据等级及其实际能支持的结论；
- 下一次人工或 Gold 检查点及触发条件；
- 需要人工处理的争议；
- 下一步。

更新已有 README 或状态页。若 README 已承载其它用途，只更新一个明确标记的状态区域，不覆盖用户正文，也不再创建另一份首页。
