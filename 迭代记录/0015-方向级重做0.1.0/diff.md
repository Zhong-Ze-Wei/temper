# 0015 · 方向级重做 v0.1.0

日期：2026-08-27 ｜ 版本关系：v0.0.8 → v0.1.0（方向级重做，跳 minor）

## 目的

0.0.8 之后，两组各自独立的 4-agent 并发审查（本会话审查 + 已归档的《评测/并发审查-设计符合度.md》）收敛到同一结论：过度工程（仓库 8665 行中约 6000 行是元层）、状态纪律崩（README / state / 版本说明三处矛盾）、判断层不可执行、14 代 0 部署（安装副本仍 v0.0.1）、真实使用反馈（评测第 6 层）始终为 0。

根因：自举的唯一反馈源是自己 → 每个 failure mode 都是文档治理问题 → 修出来的每个机制也是文档治理机制 → 机制自我繁殖。

用户裁决：方向级重做——"不是做一个很重的 skill，而是做一个真正能帮助人的 skill"。

## 方法（新骨架）

- **四分区**：当前权威 / 过程 / 沉淀 / 冻结（+ labs 实验区），职责固定、形态自由
- **三条纪律**：跑之前方法先落盘 → 跑之后立刻对照 → 每 3-5 代归档汇报
- **四种进场**：A 冷启动 / B 已有散件 / C 遗留混乱 / D 日常运转
- **硬约束与自由度的边界**：分区职责、纪律时机、诚实边界、冻结区保护 = 硬；目录形态、层判断、结构多少 = 自由（须引用证据）
