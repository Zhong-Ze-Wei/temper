# 淬炼

你是来把一个还不太稳的任务做稳的。可能目标都没想清，可能能跑但老翻车。淬炼不管你的任务现在多糊，只要值得持续改进，它都能带你一轮轮把它弄明白、弄稳。

## 你不用学的四件事

每次跟淬炼打交道，它只给你四样东西，别的它自己消化：

1. **现在是什么情况** —— 它先翻了哪些东西、发现了什么、现在怎么看。
2. **这一轮要干嘛** —— 当前真正缺的是业务理解、评测、数据还是方法；一轮只办一件关键事。
3. **要不要你** —— 只有它缺你脑子里的信息、要你拍板、或方向要变时才会找你。一轮最多找你 2 次。
4. **折腾完你能看到什么** —— 本轮结果、跟上一版差在哪、证据能撑到哪、下一步去哪。

它不会一上来让你选什么 Discovery、Epoch、Candidate。这些是后台的事，你要想听它才讲。

## 怎么开始

### 第一次用，直接说就行

不用组织语言，把现在的任务和卡住的地方丢过来，比如：

> "我有个法规资讯分析，能跑，但合并不稳定。我拿不准是该改 Prompt 还是先找业务把口径定死。"

它会依次回你三句：

- **【判断】** 先不动你的东西，只读一圈项目（README、定义、方法、评测、跑过的记录、最近改动），告诉你真正缺什么、到哪一步了、值不值得继续。**你说改之前，它只看不动。**
- **【计划】** 这一轮只做一件关键事，说清怎么做、证据能撑到什么程度。
- **【需要你】** 只有系统里查不到、不问你就会做错方向的事才问你。它能自己看到的，不让你重复讲。

然后第一轮就开了。

### 每轮怎么跑

每轮固定四步：先看现状 → 只问必要的问题 → 跑一版并留痕 → 更新当前视图。

**每次结束交四样**：结果 / 跟上一版的差异 / 证据能撑到哪 / 要你拍板的事或下一步。

## 它干什么，你干什么

| 它自己干 | 才轮到你 |
| --- | --- |
| 翻项目、找现状和矛盾 | 业务事实、系统里查不到的信息 |
| 设计这一轮最小的改动 | 目标或定义变了 |
| 跑、做对比、找系统性问题 | 高风险的决定 |
| 记下每一代的证据和决定 | 关键回归或方向吵起来了 |
| 判断哪些能自己验证 | 要不要收下新版本 |

**它不会**：把你当每轮结果的审核员；编系统里没有的业务规则；目标还糊着就说这代更好；不问你就不动你的文件、不对外发任何东西。

---

## 值不值得用它，先问一句

动手前先想一个问题：

> 下次再遇到同类任务，这次留下的东西能不能让结果明显好一点？

- **能** → 继续，搭个最小的迭代架子。
- **不能 / 一次性的活 / 完全确定的事** → 不搭循环，直接干完拉倒。

这句判断是开场就该有的，不是藏在哪里的规矩。它管"要不要迭代"，至于"怎么迭代"是另一回事。

## 后台是怎么想的（你想听再展开）

下面是它干活时用的逻辑。首次用不用懂，想搞明白"它凭什么这么判断"时再看。

### 判断缺什么

看任务到哪一步了：**Discovery**（目标还糊，先弄清问题）→ **Formation**（搭个能看的初版）→ **Eval Building**（把反馈搞可信）→ **Optimization**（能正经比版本了）→ **Stabilization**（上生产要管得严）。

控制到多严，看风险：**轻量 / 标准 / 严格**。高风险、不可逆、上生产、要审计的，至少按严格来。

缺什么、要多少控制、怎么迭代、人在哪介入，这四件事各算各的，别搅在一起。细节在 `references/assessment.md`。

### 决定怎么迭代

先看这次是哪种变化：**替换 / 增量 / 并行 / 分流 / 实验 / 契约变化**。后三种不一定非要替换旧的。增量就重点比受影响的 Case 再回归没动的部分；分流就分场景评，别用一个平均分压平差异；契约变化（"什么叫做好"变了）要单独过一次评审。细节在 `references/strategy-selection.md`。

### 搭多少结构

先复用已有的，缺啥补啥；不建空目录；一个职责只留一份权威来源。简单任务就保持最简。细节在 `references/project-structure.md`。

### 每轮留什么

每代至少留下：目的 / 方法 / 产物放哪 / 相对上一代改了啥 / 评测和失败 / 决定和下一步。证据分层用，不用每轮都跑最贵的那层。版本状态分**当前工作 / 最近业务校准 / 生产**，别拿便宜证据冒充业务确认。细节在 `references/generation-traceability.md`。

### 跟用户怎么说话（这版新加的）

第一次进入和每轮交付的固定格式，见 `references/interaction-contract.md`。

## 这版不做什么

不建常驻的自动循环、复杂的 Runtime、Hooks、多 Agent 的图、跨项目面板，也不接外部执行。不自动改多轮、不自动发布。真用出问题了，再按问题加能力，不为搭而搭。
