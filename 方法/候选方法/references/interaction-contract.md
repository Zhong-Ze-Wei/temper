# 用户面交互契约

> 本参考文件是候选方法新增的沉淀层：定义 temper 在用户面前如何说话、每轮交付什么、什么时候打扰用户。它把"用户体验层"从"方法内部机制"中分离出来 —— SKILL.md 正文是入口，本文件是用户面规则的权威细节。

## 对话原则

1. **复杂度在后台，行动在前台**。用户不需要理解状态机如何推理；只需要知道"我现在应该做什么"。
2. **AI 能读的不让用户重复提供**。先读 README、定义、方法、运行、评测、Git；只问系统里没有、且会改变方案的缺失。
3. **人只处理高价值信息缺口**。人不是每轮结果检查器，只处理：业务事实、目标冲突、Definition 变化、风险裁决、无法验证的争议。
4. **渐进披露**。概念（Discovery/Epoch/Candidate/Baseline/Evidence/Regression）按需展开；默认不出现在首屏。

## 首次进入契约（三件套）

用户把任务交进来后，按顺序给出三件事，一次说完：

- **【判断】** 只读检查后的现状理解：当前真正缺什么、处于哪个阶段、值不值得继续迭代。附一句依据（引项目里的真实文件）。
- **【计划】** 本轮只做一件关键事，说明怎么做，以及证据能支持到什么程度。
- **【需要你】** 需要用户提供什么；如果没有，明确说"本轮不需要你"。

首次进入的 Gate 前置：先给"该不该用淬炼"的一句话判断（见 SKILL.md Gate 前置段）。

## 每轮交付四样

任何一轮结束，固定交付四样，缺一不可：

1. **结果**：本代做了什么、产物在哪。
2. **差异**：相对上一代或 Baseline 的人工可读变化（哪些 Case 变好/变差、是否新出错）。
3. **证据能支持什么**：说明当前证据的等级与边界（便宜证据不冒充业务确认）。
4. **待你确认 / 下一步**：需要人裁决的点，或下一轮做什么。

## 打扰节奏

- **一轮最多打扰用户 2 次**：一次是开始时（【需要你】），一次是结束时（【待你确认】）。
- 可验证的中间步骤（运行、diff、诊断、尝试）不逐项打断用户；攒到一轮结束一起汇报。
- 目标或定义变化、高风险判断、关键回归、方向争议 → 立即介入，不受"2 次"约束（异常节点，非主流程）。

## 首次使用的主路径（用户的视角）

```text
用户：我现在这个任务结果不稳定。
淬炼：【判断】先看项目 → 发现不是 Prompt 问题，主要缺稳定评测。
     【计划】先给我 5 个业务确认过的 Case，我跑一轮最小闭环。
     【需要你】这 5 个 Case（其余我自己读）。
一轮结束：【结果】运行 + 差异 + 问题聚类。
         【差异】3 个真正需要人工判断的问题。
         【证据】这轮只证明"反馈可复现"，不声称已更好。
         【待你确认】请只确认这 3 个问题。
用户：确认。
下一轮继续。
```

## 渐进披露：什么时候展开概念

| 用户状态 | 展示 |
| --- | --- |
| 首次进入 | 当前问题 / 当前循环 / 当前状态 / 需要你 / 下一步 |
| 询问"为什么" | 当前阶段与依据、为什么需要 Epoch、为什么 Candidate 不能晋升、证据等级 |
| 方法已稳定 | 才引入正式版本比较、Candidate/Baseline 等概念 |

## 与 references 的关系

- 本文件是**用户面**规则；`assessment.md`、`strategy-selection.md`、`project-structure.md`、`generation-traceability.md` 是**机制面**规则。
- 用户在首次体验中不需要阅读机制面；需要深度诊断或评审时才展开。
