## 这个仓库自己就是四分区的活例

| 分区 | 在这里是 |
| --- | --- |
| 当前权威 | 根 `SKILL.md`（单文件，无 references） |
| 过程 | `迭代记录/`（每代一份，最新：0015 方向级重做） |
| 沉淀 | `设计资料/` + `沉淀/AI工作文件模板.md`（项目 AGENTS.md 五节模板）+ 根目录愿景页 |
| 尺子（冻结语义） | `评测/`（默认不动；改动需记录并经用户确认） |
| 冻结 | `版本/`（历史快照；新版本用 git tag，不再建快照目录） |

后台状态：`.temper/state.json`（5 个字段）。labs/ 实验区暂无。

## 怎么用这个仓库

把任务直接说给它听即可。它每次冷启动会按序读：权威区 → 过程区最新一代 → 冻结区尺子 → 状态文件，然后先说"我理解的现状"再动手。

你只需要：

1. 给真实任务和"什么算好"的案例；
2. 被问到业务口径时给一句话裁决；
3. 每版给一句验收（收 / 退）；
4. 感觉方向不对，直接说"偏了"。

## 发布与同步

GitHub：https://github.com/Zhong-Ze-Wei/temper ｜ 方法与记录：[发布与同步.md](发布与同步.md) ｜ 快速执行：`./scripts/同步.sh <目标...>`

规矩：**同步/发布前必须问用户**。四目标 = `agents`（~/.agents/skills）→ `claude`（~/.claude/skills）→ `github` → `cskills` 注册表；每次同步登记版本号 + commit。已知坑：安装位置的 `.cskills-meta.json` 是注册表旧哈希，`cskills sync` 可能回退——以仓库为权威。

两个 temper 别搞混：根 `SKILL.md` + `版本/` 是权威副本（能改）；各安装位置是部署副本（别手改，会被覆盖）。
