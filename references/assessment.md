# 状态判断与循环强度

每次会话开头读。判断：任务值不值得建循环、处于哪个阶段、需要多少控制、最小下一步是什么。判断结果就是开场回应里的【判断】块。逐项给结论、证据和不确定性，不合成总分。

## 先看一个真实示例

场景：用户有一个法规资讯分析任务，V0 能跑，结果时好时坏。

```
【判断】处于 Eval Building：能稳定运行（README 记载方法已到 V3，
        runs/ 有 5 次运行），但没有任何可信评测——好坏全靠观感。
        值得建循环：任务每周重复，错误会累积。
【计划】1) 聚类最近 2 次运行 24 条 case 的错误类型（我来做）；
        2) 据此起草第一版 8 条回归案例（我来写）；
        3) 你从业务角度勾出最不能错的 3 条（约 5 分钟）。
【需要你】① 业务上最不能接受的错误是哪类？
            （默认：同事件被拆开 / 不同事件被合并）
          ② 现在结果谁在用？（默认：只有你自己看）
```

要点：每个结论都指向项目里真实存在的东西（README、runs/），没有空话；两个问题都带默认答案。

## 适用性 Gate

以下多数成立 → 直接完成任务，不建循环：

- 一次性工作或普通问答；
- 完全确定性的转换；
- 人工几分钟即可稳定完成；
- 不需要未来版本比较；
- 没有持续学习价值；
- 留痕成本明显高于潜在收益。

判断问题：下次遇到同类任务，这次留下的证据会不会让结果明显更好？不会，不建循环。

## 诊断维度

### 目标清晰度

能否回答：谁使用结果、支持什么决定；输入输出和范围边界；什么算完成；哪类错误最重要、取舍是什么；哪些还只是工作假设。目标不必一开始完整——不清楚时用真实案例或最小 V0 学习，不假装已冻结正式标准。

### 反馈质量与成本

可信反馈尽量满足：能追到具体 Case 和原始依据；可重复计算或有明确人工裁决者；衡量的是任务价值而不只是格式正确；同一轮比较期间含义稳定；能识别关键回归而不只给平均分。结构校验、AI 自评、单次观感可以是信号，但不能单独证明质量提升。同时看成本、延迟、覆盖面、频率：昂贵 Gold 可按批次或风险触发，便宜证据负责日常筛错。

### 版本关系

本次变化是替换 / 增量 / 并行 / 分流 / 实验 / 契约变化（详见 strategy-selection.md）。版本号递增不代表必然替换；契约变化需要 Epoch Review。

### 人工参与与运行节奏

任务运行和修改多频繁；人适合在哪参与：每代复核、抽样、周期检查点、异常介入、发布 Gate，或组合。记录用户已表达的偏好，不强迫每代做昂贵人工工作。

### 风险与可逆性

错误成本、外部影响、规模、可回滚性、权限、合规、安全。高风险或不可逆是严格控制的硬触发，不代表必须用复杂 Graph。

### 项目成熟度

是否已有：可重复 V0；当前方法或 Baseline；工作 / 校准 / 生产版本的区别；可版本化输入和产物；Trace；Eval、Gold、Regression；Candidate 与正式版本的区分。

## 阶段判断

选当前主要阶段；不同子任务处于不同阶段时给主阶段并标局部分支，不把整个仓库压成一个状态。

- **Discovery**：目标、边界或真问题仍模糊。产出当前理解、未知项和学习问题；可以有代际记录，但不宣称性能版本可比。
- **Formation**：目标够支持行动，还没有可重复 V0。搭最小框架，拿第一份可观察产物。
- **Eval Building**：能运行、目标相对清楚、缺可信后验。运行与建设 Case / Gold / Regression 并行。
- **Optimization**：有可重复工作版本和足够证据。围绕差异、诊断、回归、校准检查点工作；不要求每代昂贵 Gold。
- **Stabilization**：高频、生产或高风险使用。重点转向关键回归、审计、回滚、有限人工 Gate。

## 循环强度

阶段回答「现在缺什么」，强度回答「需要多少控制」，策略回答「怎样迭代」。三者分开判断；严格控制不等于频繁 Gold。

- **轻量**：低风险、可回滚、探索性强、规模小。理解 → 一次运行 → 观察 → 最小修改 → 重跑记录。
- **标准**：重复任务、需要版本比较。明确 Epoch、版本关系、工作版本、人工可读 Diff、回归、状态变更规则。
- **严格**：高风险、不可逆、生产、强审计。按实际风险增加 Baseline Lock、关键样本、完整 Trace、人工裁决、风险 Gate、回滚；不因此默认引入多 Agent 或 Runtime。

硬规则：出现生产外部写入、合规 / 安全责任、不可逆结果或重大损失风险时，至少采用严格风险控制——即使任务仍在 Discovery。

```
关键依据：…（引用项目中的真实文件、运行或案例）

```

不重复用户已知信息。每个判断尽量引用项目里的真实文件、运行或案例。
